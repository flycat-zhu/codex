## 二、业务目标
| 字段 | 内容 |
| --- | --- |
| 为什么做 | 支撑重点客户下周内部汇报演示，提升订单检索效率 |
| 解决谁的问题 | 客户运营人员需要快速查看某行业客户订单 |
| 预期结果 | 用户可在订单列表中按行业快速筛选并浏览对应订单 |
| 关键使用场景 | 演示场景、日常订单处理场景 |

## 三、功能说明
| 字段 | 内容 |
| --- | --- |
| 涉及页面/模块 | 订单列表页 |
| 功能描述 | 在列表页顶部新增“客户行业”筛选项，用户选择后仅展示对应行业的订单 |
| 用户操作流程 | 进入订单列表 -> 选择行业 -> 查看筛选结果 -> 分页浏览 -> 清空筛选恢复全部 |
| 依赖接口/数据 | 订单列表查询接口、客户行业字段 |

## 四、本次范围
1. 支持单选行业筛选。
2. 支持筛选后分页展示。
3. 支持清空筛选恢复默认列表。

## 五、本次不做
1. 不支持多条件组合筛选。
2. 不支持导出结果按行业维度联动。
3. 不补历史缺失行业数据。

## 六、规则说明
| 字段 | 内容 |
| --- | --- |
| 交互规则 | 筛选控件位于列表顶部，默认值为“全部” |
| 数据规则 | 行业字段来自客户档案；行业为空的数据不纳入行业筛选结果 |
| 权限规则 | 沿用订单列表现有权限模型 |
| 异常场景 | 筛选结果为空时展示空态提示；切换分页后保留筛选条件 |
| 兼容性要求 | 支持当前主流浏览器，风格与现有列表保持一致 |
| 文案/提示要求 | 空态文案使用“当前筛选条件下暂无订单” |

## 七、验收标准
1. 选择某行业后，列表仅展示该行业对应订单。
2. 清空筛选后恢复全部订单数据。
3. 分页切换时筛选条件保持有效。
4. 原有查询、排序、分页功能不受影响。
5. 空数据场景和行业为空场景表现正常。

## 八、风险与注意事项
| 字段 | 内容 |
| --- | --- |
| 已知风险 | 历史订单行业字段缺失会影响覆盖率 |
| 遗留问题 | 刷新页面后是否保留筛选状态，本期不处理 |
| 特殊说明 | 本次为最小可行版本，重点满足演示和主要使用路径 |
| 范围变更处理方式 | 若新增组合筛选诉求，需重新评估，不纳入本次开发 |
